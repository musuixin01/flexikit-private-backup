# FlexiKit Stage 6 — 真实用户测试计划

> 状态：测试方案已准备；**尚未招募、尚未开始外部测试**。本计划不代表发布门槛已通过。
>
> 当前优先平台：Windows Desktop（Tauri/WebView2）；浏览器与其他终端作为兼容性补充，不以 Windows 的结果冒充全平台通过。

## 1. 测试目标与边界

本阶段优先确认真实用户能否独立完成“发现工具 → 添加 → 使用 → 组织 → 再次使用”的核心闭环，以及 Desktop Canvas / 桌宠 / AI 助手是否足够稳定；**不以增加功能数量代替产品验证**。

验证四个方面：
1. 首次使用是否能理解工作台、全部工具和本地/网页工具两类入口。
2. 工具导入、修改、搜索、收藏、排序、打开、重启恢复是否可靠，是否丢失用户设置。
3. 窗口实时缩放、系统 DPI、多显示器、离线启动、桌面 Canvas 和桌宠是否存在阻断问题。
4. 错误提示是否可理解、可恢复，敏感数据是否遵守现有隐私边界。

## 2. 试测规模与采集规则

- **目标样本**：6–10 位自愿用户；覆盖至少 2 名不熟悉产品的普通用户、2 名工具重度用户和 2 名多屏/高 DPI 用户。样本不足则继续标记“进行中”，不推断统计显著性。
- **周期**：首轮 7 天。首日无口头指引独立完成 15–20 分钟任务；此后每天约 5–10 分钟自然使用并手动记录反馈。第二轮针对阻断问题复测。
- **设备矩阵**：Windows 10/11；100%、125%、150% 缩放；单屏与双屏；不同 GPU/驱动组合；浅色、深色、系统自动主题。只记录实际覆盖的配置，不能假定所有组合均已测试。
- **测试资料**：使用无敏感信息的公开网站和明确可执行的本地样例。不得让用户公开提供 API Key、真实密码、个人文档正文或包含个人路径的未脱敏截图。
- **诊断日志**：目前仅有本机诊断能力；日志、系统配置、截图或屏幕录制均需用户先审阅并主动选择提供。**默认不自动上传、不开启隐藏遥测**。AI Prompt/Response、剪贴板、文件内容、BYOK Key、用户本地路径不可进入反馈载荷。
- **试测环境**：尽量使用隔离/测试资料，升级、卸载、数据清理只在用户同意并备份的测试环境中进行；不操作正式生产数据。

## 3. 任务脚本（首日）

测试者仅看到每项任务的“操作目标”，观察员只记录求助次数和结果，不提前告诉具体按钮在哪。

| 编号 | 用户目标 | 验收观察点 |
| --- | --- | --- |
| UT-01 | 首次启动，找到自己的工具箱 | 是否理解“工作台 / 全部工具”，能否返回工作台 |
| UT-02 | 只输入网址添加一个网页工具 | 自动名称/favicon/描述/标签是否合理，允许自定义且能重新编辑 |
| UT-03 | 添加本地程序或快捷方式 | 拖入指定区域和“选择启动程序”至少一条路径可用；真实图标、名称与分类正确 |
| UT-04 | 一次拖入多个本地程序 | 候选在导入框内可见，逐个确认/跳过；重复文件不会误添加 |
| UT-05 | 搜索、分类、收藏、取消收藏 | 结果准确，切换时已有数据不丢失 |
| UT-06 | 排序、打开工具、重启后检查 | 鼠标排序跟手；真实启动，重启保留工具、图标、排序和设置 |
| UT-07 | 离线启动并浏览本地工具 | 不露原生浏览器错误页；联网功能明确提示，不清空会话 |
| UT-08 | 操作桌宠和 Canvas 组件 | 鼠标点击与拖动可用，移动/缩放/锁定/重启恢复无异常 |
| UT-09 | 右边框、底边框和右下角连续缩放 | 无黑白露底、白闪、内容截断；松开后原玻璃/动效恢复；主题切换不出错 |
| UT-10 | 全局搜索与键盘操作 | 快捷键/方向键/Enter/Esc 可完成主要流程，焦点可见 |
| UT-11 | 打开 AI 助手（自愿） | 不授权文件或剪贴板不会被读取；BYOK 只在用户显式操作时使用 |
| UT-12 | 查看设置与数据管理 | 能找到主题、隐私、备份/清除说明，危险操作需要确认 |

Web 端另做窄屏 390/640/860px 基础排版检查；不得把 Desktop 原生功能当作 Web 已支持功能。

## 4. 专项：窗口缩放与多屏

每个实测配置记录 Windows 版本、WebView2 版本（如可安全获取）、显示器分辨率/缩放比例、GPU/驱动（如用户愿意提供）、应用版本与主题。

操作顺序：
1. 恢复非最大化窗口，分别拖右边、底边和右下角，各连续往返不少于 5 次；观察边框实时移动时的画面，**不能只凭松手后的静态截图判定无闪块**。
2. 在浅色、深色、系统自动主题各进行至少一组；确认桌宠和透明 Canvas 不出现实底矩形。
3. 在 100%/125%/150% DPI 和可用的双屏混合 DPI 下重复；窗口跨屏后检查坐标、鼠标命中、布局和缩放恢复。
4. 记录黑/白块持续时间（主观短暂/明显/持续）、大致位置、是否可复现。允许用户**自愿**提交已遮挡敏感内容的短视频。

当前已有证据：Web/Desktop 构建、Rust 编译及窗口原生尺寸变化测试通过；2026-10-08 进一步通过 Win32 真实鼠标按住右边框触发宽度由 1200px 增至 1315px，并恢复原几何。**动态黑白闪块和跨 DPI 人工视觉终验仍待完成**。

## 5. 评价与发布门槛（目标，非当前成绩）

| 指标 | 目标与判定 |
| --- | --- |
| 关键任务完成率 | UT-01/02/03/05/06/07/09 各项目标 ≥90%；任何阻断必须另立缺陷 |
| 首次添加工具 | 记录完成耗时、中途停顿和帮助次数；比较首轮与复测，不制造“已达标”结论 |
| 稳定性 | 无未关闭的 P0/P1；任何丢数据、启动崩溃或隐私越界均阻止进入下一发布门槛 |
| 可靠性 | 记录每次冷启动、真实工具启动、Canvas 恢复及窗口缩放失败次数 |
| 性能 | 已有手动按需的本地性能测量工具及隔离版/正常开发版首轮 CPU、内存、启动检查点基线（见 docs/STAGE6_PERFORMANCE.md）；仍需优化 Release、Canvas 和真实用户可见首屏，暂不设未经验证的 CPU/内存绝对发布结论 |
| 留存与易用性 | 观察 7 日实际返回情况，区分未参与与使用后流失；至少复测一次主要易用性阻断 |

问题级别：**P0** 数据破坏/凭据泄露/无法安全使用；**P1** 主要闭环被阻断或可重复启动崩溃；**P2** 明显功能/显示不稳定但有绕行；**P3** 文字、视觉或低频体验问题。

停止条件：发现 P0、重复出现的 P1、日志疑似包含秘密或测试操作危及用户资料时立即停止相应试测。不得为追求样本数强行继续。

## 7. 执行顺序与完成定义

1. 本文档评审并固定测试任务、渠道、隐私说明和测试账号/样例。**此项是计划编制，不等于开始真实用户测试**。
2. 已完成最小化本地 Crash / Error 基线（见 docs/STAGE6_DIAGNOSTICS.md）：仅类别计数、默认本机保留、用户主动复制；保留历史日志风险提示和人工复制终验。Stage 6 性能指标已启动，采用 docs/STAGE6_PERFORMANCE.md 的手动测量工具，不静默采集用户数据；正式发布性能门槛仍未完成。
3. 建立最少一个不含真实用户数据的内部冒烟记录；准备安装包/测试说明和反馈接收方式。
4. 经自愿同意后进行 7 日试测；分批修复、回归、复测，并将对应证据更新到 `docs/STABLE_CHECKLIST.md`。
5. 只有真实用户完成数据、稳定性与核心产品方向得到验证，才能判断 Stage 6 的完成门槛；不得因测试计划文档创建而提前进入商业化阶段。
