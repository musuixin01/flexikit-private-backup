# FKI-20261010-001 · 手动爬虫入口匿名可触发
## 现象
10 个 POST /crawler/* 手动维护路由原来允许匿名触发，存在未经授权的资源消耗风险。

## 复现
通过原始路由权限审查确证问题；不在公网/真实用户服务主动复现滥用行为。在独立 Nest HTTP 测试服务中验证 401/403/201/429。

## 根因及证据
原 Controller 手动路由缺少统一 JwtAuthGuard 和 AdminAccessGuard；没有单实例手动任务互斥/来源冷却限制。

## 修复与变更
backend/src/crawler/crawler.controller.ts 已统一加授权，另新增 backend/src/crawler/crawler-manual-trigger.gate.ts，单实例手动抓取互斥、来源 60 秒冷却。定时爬虫仍走原路径。

## 验证与边界
独立 NestJS 编译/TypeScript 和最小真实 Nest HTTP 10 路由、401/403/201/429 PASS，爬虫与账号仓储为隔离 stub；生产多实例/网关限流、执行预算及真实部署尚未验收，不标 VERIFIED。

## 防复发
保留 backend/scripts/crawler-manual-security-regression.mjs 和 backend/scripts/stage6-crawler-http-isolated.mjs，正式公网门禁增加全局限流/取消/告警验证。
