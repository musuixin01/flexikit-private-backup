# FKI-20261010-004 · 编辑工具 read_revision 与目标不匹配
## 现象
对 package.json 的结构化修改传入另一文件的 read_revision，触发 read_revision_path_mismatch，整批编辑被原子拒绝。

## 复现
读取修订与文件路径必须严格对应；不应故意在当前项目重放错误编辑。

## 根因及证据
把不同目标文件的读取修订号混用，工具校验正确拒绝，失败操作未修改文件。

## 修复与变更
重新按文件路径获取对应修订号，唯一锚点精确编辑并先 dry-run 再 apply；本次操作恢复成功。

## 验证与边界
历史 errors-log 明确记录编辑恢复成功；VERIFIED 仅表示该次操作流程可继续，不保证所有工具场景无缺陷。

## 防复发
批量编辑逐文件维护 path/revision 配对，若遇版本变化或行尾问题先读新内容而非强制覆盖。

补充（2026-10-10，隔离 Git 备份预检）：第一次从私有备份树制作临时索引时使用不带基线的 git diff --cached，Git 默认与本地 master HEAD 比较，把此前私有快照已包含的约 120 个修改误计为本次变更；白名单守卫拒绝推送，**未发生远程写入或本地工作树变动**。后续必须显式使用 git diff --cached <上次私有备份 SHA> --name-only 核对本次增量，再以非强制 fast-forward 更新私有备份。
